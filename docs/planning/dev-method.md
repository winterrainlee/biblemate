# 개발 방법론
기능 개발 시 방법론에 대해 다룬 문서입니다.

## 1) 목표 정렬과 범위 설정
핵심 가치(말씀 읽기/묵상/진도·UX)를 다시 확인하고, 다음 버전에서 개선·확장할 포인트를 세분화합니다. 예) 이중 역본 전환 UX 개선, 노트 자동저장 안정성, 모바일 반응형 최적화 등.

기능 영역별로 기대 결과(사용자 스토리·정량 목표)와 “완료” 정의를 명확히 적습니다. 읽기/노트/진도/설정 네 축으로 나누면 추적이 쉽습니다.

## 2) 구조 기반의 워크스트림 쪼개기
백엔드: server/routes/의 도메인별 라우트(bible/highlights/notes/reading) 단위로 이슈를 나누고, 스키마 변화가 필요한지 먼저 검토합니다.

프론트엔드: client/src/pages/ReadingDashboard.jsx 등 페이지 단위로 UX 변화 범위를 정의한 뒤, 공용 컴포넌트(components/)와 서비스 래퍼(services/api.js) 영향도를 체크합니다.

데이터 흐름: 장·구절 조회, 하이라이트, 노트 저장, 읽기 로그의 요청 순서를 기준으로, 병목이 생길 지점(예: 저장/조회 동시성, 캐싱 필요성)을 사전에 명세합니다.

## 3) 계획 산출물 템플릿
로드맵 표: 기능 테마별(읽기/노트/진도/설정)로 에픽 → 스토리 → 기술 태스크를 계층화하고, 위험도·복잡도 점수로 우선순위화.

인터페이스 계약: 변경 예상 API의 요청/응답 스키마와 실패 케이스를 간단한 표로 정리(예: 새 필터 추가 시 GET /reading/logs?book=... 응답 필드 정의).

UI 영향도 지도: 페이지/컴포넌트/스타일 파일 경로를 적시해 개발자가 바로 위치를 찾도록 합니다.

## 4) 실행·검증 루프
빠른 검증을 위해 페이지별로 최소 단위의 “기능 플래그”나 “옵션 토글”을 두어 부분 배포/리뷰를 쉽게 합니다.

QA 시나리오를 데이터 흐름 단계(조회→하이라이트→노트→저장) 순서로 작성해 회귀 범위를 줄입니다.

## 5) 협업·온보딩 최적화
새 기여자에게는 npm run dev 등 기본 실행 경로와 백엔드만 돌리는 옵션을 함께 안내하여 셋업 시간을 줄입니다.

PR 템플릿에 “영향 범위(백엔드 라우트/프론트 페이지/스타일)”, “API 계약 변화”, “데이터 마이그레이션 유무” 항목을 포함시키면 리뷰 효율이 올라갑니다.
