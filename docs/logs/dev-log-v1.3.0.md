## 🔍 Retrospective (회고)

### 1. 백업 데이터의 `id` 필드 의존성
- **문제**: 구버전 백업이나 임의로 수정한 백업 파일에 `id`가 없을 경우, SQLite Insert 쿼리 바인딩에서 `undefined` 에러가 발생하며 서버가 멈춤.
- **해결**: `server/routes/backup.js`에서 모든 레코드 처리 시 `id` 필드를 명시적으로 체크하고, 없으면 `null`을 할당하여 DB의 AUTOINCREMENT 기능을 활용하도록 수정함.
- **교훈**: 클라이언트나 외부 파일에서 오는 데이터는 언제나 불완전할 수 있음을 가정하고, DB 레이어 직전에서 Default Data Handling을 철저히 해야 함.

### 2. JSON 파싱과 이스케이프 문자
- **문제**: 테스트용 백업 파일(`v130.json`)을 수동으로 생성하는 과정에서, 본문 내의 큰따옴표(`"`)를 이스케이프하지 않아 Client에서 `JSON.parse` 실패 발생. 사용자에게 구체적인 원인(Syntax Error)을 알려주지 못하고 "읽을 수 없음"으로만 처리됨.
- **해결**: Node.js 스크립트를 통해 `JSON.stringify`로 안전하게 파일을 재생성하여 해결.
- **교훈**: 테스트 데이터 생성 시에도 수동 편집보다는 스크립트를 사용하여 휴먼 에러를 방지해야 함. 또한, 프론트엔드 에러 핸들링 시 `SyntaxError`와 같은 구체적인 원인을 파악하여 가이드해주는 것이 좋음.

### 3. 중복된 DOM 조작 코드로 인한 에러
- **문제**: Export 기능 구현 중 `document.body.removeChild(a)` 코드가 실수로 중복되어 다운로드 후 콘솔 에러 발생 및 실패 팝업 표출.
- **해결**: 중복 코드 제거.
- **교훈**: Copy & Paste 나 자동 완성 사용 시 코드 중복 여부를 꼼꼼히 리뷰해야 함. 특히 DOM 조작은 Side Effect가 크므로 주의 필요.

### 4. 브라우저 자동화 테스트의 한계
- **문제**: 로컬 개발 환경에서 CDP(Chrome DevTools Protocol) 연결 불안정으로 인해 브라우저 자동 테스트(`browser_subagent`)가 자주 실패함.
- **대안**: `curl`이나 Node.js 스크립트(`fetch`)를 이용한 직접 API 호출 테스트로 전환하여 검증 수행.
- **교훈**: E2E 테스트가 불가능할 경우를 대비해 Integration Test Script(순수 JS)를 준비해두는 것이 효율적임.
