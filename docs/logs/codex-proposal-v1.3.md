# Codex 제안: v1.3 추가 우선순위 (로드맵 외)

## 가정 (Assumptions)
- 현재 백업 범위(데이터만 포함) 및 전체 덮어쓰기(Full Overwrite) 방식 유지.
- 하위 호환성이나 UI 설정 백업은 고려하지 않음.
- 이 항목들은 `docs/guides/roadmap.md`에 등재되지 않은 내용임.

## 우선순위 목록 (Priority List)

### P0 (필수 - Must)
1) **백업 Import 용량 제한 및 413 에러 처리**
- **문제**: `express.json()` 기본 설정은 약 100kb임. 용량이 큰 백업 파일은 413 에러나 파싱 에러로 실패할 수 있음.
- **제안**: `/api/backup/import` 엔드포인트에 대해 용량 제한을 늘리고(예: `5mb`), 초과 시 명확한 `PAYLOAD_TOO_LARGE` 에러를 반환하도록 수정.
- **수정 대상**: `server/index.js`, `server/routes/backup.js`.

2) **필수 필드 외 데이터 무결성 검사**
- **문제**: 필수 필드는 존재하지만, 유효하지 않은 값(예: `chapter_from > chapter_to`, 비표준 날짜 형식, 정수가 아닌 숫자 등)이 포함된 경우 데이터가 손상될 수 있음.
- **제안**: 날짜 및 숫자 필드에 대한 값 검증 로직을 추가하고, 문제되는 레코드를 지목하는 상세한 `INVALID_SCHEMA` 에러 제공.
- **수정 대상**: `server/routes/backup.js`.

### P1 (권장 - Should)
3) **서버 주도 Export 다운로드 헤더**
- **문제**: 현재 다운로드 처리가 전적으로 클라이언트 주도라 브라우저마다 동작이 다를 수 있고 파일명 생성 로직이 중복됨.
- **제안**: `/api/backup/export` 응답 시 `Content-Disposition` 및 `Content-Type` 헤더를 설정하여 서버가 파일명과 다운로드 동작을 제어하도록 변경. 클라이언트는 해당 엔드포인트로 이동하기만 하면 됨.
- **수정 대상**: `server/routes/backup.js`, (선택사항) `client/src/pages/Settings.jsx`.

4) **인증 상태를 고려한 백업 UX**
- **문제**: 세션이 만료된 경우 백업 동작이 일반적인 에러로 실패함.
- **제안**: `401`/`403` 에러 발생 시, 별도 메시지를 표시하고 재로그인을 유도(또는 로그인 페이지로 리다이렉트).
- **수정 대상**: `client/src/pages/Settings.jsx`, (선택사항) `client/src/services/api.js`.

### P2 (좋음 - Nice)
5) **백업 왕복(Round-trip) 테스트 스크립트**
- **문제**: Export -> Import -> Export 과정이 안정적인지 검증하는 자동화 수단 부재.
- **제안**: `/api/backup/export` 호출 후 다시 Import 하고 레코드 수를 비교하는 가벼운 스크립트 추가.
- **수정 대상**: `scripts/` (새 테스트 스크립트), (선택사항) 문서 추가.

6) **UI 내 Export 메타데이터 노출**
- **문제**: 사용자가 백업 파일이 어느 앱 버전에서 생성되었는지 확인하기 어려움.
- **제안**: 성공 토스트 메시지나 정보 행에 `app_version`과 `exported_at` 정보를 표시.
- **수정 대상**: `client/src/pages/Settings.jsx`.


## 로드맵 기반 v1.3 후보 (추가)
- 전제: 로드맵의 “백업 안정성 강화” 항목은 이미 v1.3 스펙/PR에 반영되어 있으므로 제외.

### P0 (빠른 효과/저위험)
1) **[Patch] 읽기 완료 버튼 UX 개선**
- 로드맵: `읽기 완료 버튼 개선`
- 이유: 범위가 좁고 리스크가 낮아 v1.3에 넣기 적합.

2) **[Minor] 부분 읽기 범위 체크**
- 로드맵: `Verse 범위 체크`
- 이유: 기록 정확도를 높이고 기존 로직에 국소적으로 추가 가능.

### P1 (중간 난이도)
3) **[Minor] 화면 분할 비율 조정**
- 로드맵: `화면 분할 비율 조정`
- 이유: UX 개선 체감이 크고 설정 항목으로 격리 가능.

4) **[Minor] 마크다운 노트 지원**
- 로드맵: `마크다운 노트 지원`
- 이유: 기능 효용이 높지만 렌더링/편집 방식 결정이 필요.

### P2 (범위 넓음/보류 가능)
5) **[Minor] PWA 오프라인 지원**
- 로드맵: `오프라인 지원(PWA)`
- 이유: 서비스 워커/캐시 정책 설계가 필요해 일정 리스크가 큼.

6) **[Minor] 통계 강화 또는 읽기 계획**
- 로드맵: `통계 기능 강화`, `읽기 계획`
- 이유: 데이터 집계/UI 설계가 필요해 1.3 범위를 넘어갈 가능성 있음.
## 성공 기준 (Success Criteria)
- Import 시 파서 에러 없이 대용량 백업 파일 수용 가능.
- 구조적으로 유효하지 않은 데이터 Import 시 조치 가능한 명확한 에러 반환.
- 모든 브라우저에서 원클릭으로 안정적인 Export 다운로드 가능.
- 사용자가 백업 관련 에러를 명확히 이해하고 대처 가능.
