# BibleMate 모바일 UX 최종 조정안 v2

> 목표: 기존 최종 조정안을 "방향성 문서"에서 "바로 설계·티켓화·검증 가능한 실행 문서" 수준으로 끌어올린다.
> 범위: 코드 수정은 포함하지 않고, 모바일 UI/UX 개선 방향과 우선순위, 수용 기준, 검증 기준을 정리한다.

---

## 0. 결론

BibleMate의 모바일 문제는 단순한 반응형 미흡이 아니다. 데스크탑에서 강점이던 3컬럼 묵상 구조가 모바일에서 사라졌는데, 그 기능을 대신할 모바일 전용 흐름이 충분히 설계되지 않은 것이 핵심이다.

동시에 모바일 브라우저 특유의 기반 문제도 크다. `100vh`, safe-area, 키보드, 내부 스크롤, 스와이프 충돌이 해결되지 않으면 어떤 UI 개선도 체감이 흔들린다.

따라서 최종 개선 순서는 다음이 가장 안전하다.

1. 모바일 화면 안정화: 안 잘리고, 안 가려지고, 입력 중 데이터가 사라지지 않게 한다.
2. 구절 묵상 작성 흐름 재설계: 중앙 팝업을 바텀시트/전체 화면 작성으로 바꾼다.
3. 데스크탑에서 사라진 묵상 패널을 모바일 방식으로 복구한다.
4. 성경 읽기 화면을 말씀 중심으로 압축하고, 하단 액션으로 한 손 흐름을 만든다.
5. 묵상일지의 회고 흐름을 복구한다.
6. 읽기표, 가독성 설정, 접근성, 성능, 죽은 코드를 정리한다.

## 1. 10점 기준

이 문서가 목표로 삼는 "10점짜리 모바일 조정안"은 아래 조건을 만족해야 한다.

| 기준 | 설명 | 합격 기준 |
|---|---|---|
| 모바일 안정성 | Safari/Chrome/PWA에서 하단 잘림과 키보드 가림이 없어야 한다. | 읽음 버튼, 저장 버튼, 토스트가 safe-area 안에 보인다. |
| 묵상 핵심성 | 개인 묵상 앱의 주 행동은 하이라이트가 아니라 묵상 작성이어야 한다. | 구절 선택 후 1탭 안에 묵상 작성에 들어간다. |
| 기존 묵상 접근성 | 데스크탑의 양쪽 묵상 패널 역할이 모바일에서도 유지되어야 한다. | 현재 장의 기존 묵상을 1탭 이내로 볼 수 있다. |
| 읽기 몰입 | 본문보다 조작 UI가 먼저 크게 보이면 안 된다. | 첫 화면에서 본문 영역이 시각적으로 과반을 차지한다. |
| 회고 가능성 | 과거 묵상으로 쉽게 이동해야 한다. | 3주 전 일지에 2탭 이내로 이동한다. |
| 데이터 안전 | 입력 중 장/날짜가 바뀌어 내용이 유실되면 안 된다. | 편집 중 스와이프/뒤로가기/탭 전환 시 보호 장치가 작동한다. |
| 한 손 조작성 | 자주 쓰는 행동이 엄지 영역에 있어야 한다. | 읽음 표시, 다음 장, 묵상일지 이동이 하단에서 가능하다. |
| 접근성 | 작은 아이콘만으로 중요한 액션을 수행하면 안 된다. | 주요 터치 타깃은 44px 이상이고 `aria-label`이 있다. |
| 성능 | 기록이 많아져도 날짜/장 이동이 버벅이지 않아야 한다. | 전체 기록 재요청을 줄이고 필요한 범위만 로드한다. |
| 검증 가능성 | 개선 완료 여부가 주관적 감상에만 의존하면 안 된다. | 기기별 테스트 매트릭스와 수용 기준을 통과한다. |

## 2. 설계 원칙

### 2.1 말씀 먼저

모바일 첫 화면은 기능 목록이 아니라 말씀을 보여줘야 한다. 역본, 책, 장 선택은 필요하지만 늘 크게 노출될 필요는 없다.

### 2.2 묵상은 한 탭 안에

마음에 걸린 구절을 눌렀을 때, 사용자는 기록하려는 상태다. 모바일에서는 `구절 탭 → 묵상하기`가 최우선 흐름이어야 한다.

### 2.3 기록은 절대 잃지 않는다

묵상 앱의 신뢰는 기록 안전성에서 나온다. 입력 중 스와이프, 날짜 변경, 장 변경, 탭 전환, 뒤로가기에서 draft 보호가 필요하다.

### 2.4 데스크탑 기능을 숨기지 말고 변환한다

달력, 현재 장 묵상, 통계, 읽기표는 데스크탑 사이드바에서 사라져도 된다. 하지만 모바일 대체 동선은 반드시 있어야 한다.

### 2.5 상단은 맥락, 하단은 행동

상단은 "지금 무엇을 읽고 있는지"를 알려준다. 하단은 "지금 무엇을 할 수 있는지"를 제공한다.

## 3. 최종 모바일 정보 구조

### 3.1 성경 읽기 화면

모바일 성경 화면은 다음 네 영역으로 정리한다.

1. 압축 헤더: 앱 탭과 보조 액션.
2. 본문 맥락 바: 현재 본문, 역본, 이어 읽기 맥락.
3. 말씀 본문: 구절과 묵상 표시.
4. 하단 액션 바: 이전 장, 읽음 표시, 다음 장, 일지 이동.

권장 와이어프레임은 아래와 같다.

```text
┌──────────────────────────────┐
│ BibleMate   [성경] [묵상]  ⋯ │  ← 높이 최소화
├──────────────────────────────┤
│ 오늘 이어 읽기 · 창세기 12장 ▼ │  ← 책/장/역본 상세 선택은 바텀시트
├──────────────────────────────┤
│ 1 여호와께서 아브람에게... 📝 │
│ 2 이에 아브람이 여호와의...   │
│ 3 너를 축복하는 자에게는...   │
│                              │
│ [이 장의 묵상 3개 보기]       │  ← 접이식 또는 하단 시트
│                              │
├──────────────────────────────┤
│  ‹ 이전   오늘 읽음 표시   다음 › │  ← safe-area 반영
└──────────────────────────────┘
```

핵심은 상단을 줄이고, 행동은 하단으로 내리는 것이다. 본문 선택 UI는 항상 보이는 거대한 select 묶음이 아니라 `창세기 12장 ▼` 하나로 압축한다.

### 3.2 구절 액션 시트

구절을 탭하면 중앙 팝업이 아니라 바텀시트가 열린다.

```text
┌──────────────────────────────┐
│ 본문                         │
│ 3 너를 축복하는 자에게는...   │
│                              │
├──────────────────────────────┤
│ 창세기 12:3                  │
│ “너를 축복하는 자에게는...”   │
│                              │
│ [묵상하기]                   │  ← 1순위
│ [묵상 보기 2개]              │  ← 묵상 존재 시 상단 배치
│ [하이라이트] [복사] [공유]    │
└──────────────────────────────┘
```

묵상이 이미 있는 구절에서는 `묵상 보기`가 `묵상하기`와 같은 수준 또는 더 위에 나와야 한다. 📝 아이콘을 직접 탭하면 일반 메뉴가 아니라 묵상 보기로 바로 들어가는 것이 맞다.

### 3.3 묵상 작성 화면

묵상 입력은 작은 팝업이 아니라 키보드 안전 영역을 고려한 전체 화면 또는 거의 전체 화면 작성 모드로 둔다.

```text
┌──────────────────────────────┐
│ 창세기 12:3 묵상        닫기 │
├──────────────────────────────┤
│ “너를 축복하는 자에게는...”   │
│ [말씀 인용 포함 ✓]            │
├──────────────────────────────┤
│ 이 구절을 통해 주신 마음...   │
│                              │
│                              │
├──────────────────────────────┤
│ 임시 저장됨        [저장]     │  ← 키보드 위 또는 safe-area 위
└──────────────────────────────┘
```

필수 조건은 저장 버튼이 키보드 뒤에 가려지지 않는 것이다. `autoFocus`는 유지할 수 있지만, 입력 모드 전환 후 viewport 재계산과 버튼 위치 보정이 필요하다.

### 3.4 다중 구절 선택

현재 방식은 팝업이 열린 상태에서 다른 구절을 탭해 추가 선택하는 구조라 모바일에서 잘 드러나지 않는다. 모바일에서는 선택 모드를 명시한다.

```text
구절 탭
→ 바텀시트 상단에 “1개 구절 선택됨” 표시
→ 본문에서 다른 구절 탭 가능
→ 선택 수가 “2개 구절 선택됨”으로 갱신
→ [묵상하기] [하이라이트] 액션
```

선택 모드에서는 본문을 가리는 중앙 팝업이 없어야 한다.

### 3.5 묵상일지 화면

묵상일지는 날짜 회고와 작성 흐름을 함께 품어야 한다.

```text
┌──────────────────────────────┐
│ [성경] [묵상]        오늘 ⋯   │
├──────────────────────────────┤
│ ‹ 2026년 6월 10일 수요일 › 📅 │  ← 날짜 탭 시 달력 시트
├──────────────────────────────┤
│ 오늘 읽은 말씀                │
│ ✓ 창세기 12장                 │
├──────────────────────────────┤
│ 구절별 묵상 3개               │
│ 창 12:3 ...                   │
├──────────────────────────────┤
│ 자유 묵상                     │
│ [작성하기]                    │
├──────────────────────────────┤
│ 오늘의 기도                   │
│ [작성하기]                    │
└──────────────────────────────┘
```

날짜 텍스트는 반드시 인터랙션을 가져야 한다. 달력 시트, 오늘 버튼, 최근 묵상 목록 중 최소 2개가 필요하다.

### 3.6 읽기표 화면

읽기표는 단순 통계가 아니라 읽기 시작점이 되어야 한다.

```text
┌──────────────────────────────┐
│ 성경 읽기표                  │
│ 421 / 1189장 · 35%           │
│ [다음 안 읽은 장 읽기]        │
├──────────────────────────────┤
│ 창세기  ██████████ 50/50     │
│ 출애굽기 ███░░░░░░ 12/40     │
└──────────────────────────────┘
```

장 셀을 모두 44px 타깃으로 만들기는 어렵다. 대신 책 row 탭 또는 `다음 안 읽은 장 읽기` 버튼으로 진입점을 만든다.

## 4. 우선순위와 작업 단위

### Phase 0. 모바일 안정화 기반

이 단계는 모든 UI 개선보다 먼저 해야 한다.

#### MOB-001. viewport와 safe-area 정리

**문제**
`height: 100vh`와 `overflow: hidden` 중심 구조가 iOS Safari, PWA standalone, Android Chrome에서 하단 잘림과 내부 스크롤 답답함을 만든다.

**대상 파일**
`client/src/components/Layout.css`
`client/src/pages/ReadingDashboard.css`
`client/src/pages/BibleChartPage.css`
`client/src/pages/Settings.css`
`client/index.html`

**방향**

- `100vh` 의존을 줄이고 `100dvh`, `100svh`, fallback 조합을 검토한다.
- PWA standalone까지 고려해 `viewport-fit=cover`와 `env(safe-area-inset-*)`를 반영한다.
- 하단 토스트, 하단 액션 바, 바텀시트가 홈 인디케이터와 겹치지 않게 한다.

**수용 기준**

- iPhone Safari에서 하단 버튼이 브라우저 툴바나 홈 인디케이터에 가리지 않는다.
- PWA standalone에서 상단/하단 safe-area가 자연스럽다.
- 토스트가 하단 safe-area 위에 뜬다.

#### MOB-002. 키보드 대응 레이어 만들기

**문제**
묵상 입력 팝업이 중앙 fixed이고 textarea가 `autoFocus`라 키보드가 올라오면 저장 버튼이 가릴 수 있다.

**방향**

- 모바일 입력 UI는 중앙 모달이 아니라 바텀시트/전체 화면 작성 모드로 전환한다.
- 키보드가 열린 상태에서도 저장/취소가 항상 보이게 한다.
- 입력 영역은 스크롤 가능하고, 액션 영역은 하단 고정한다.

**수용 기준**

- iOS Safari에서 textarea 포커스 후 저장 버튼이 보인다.
- Android Chrome에서 키보드가 열려도 작성 영역이 화면 밖으로 밀리지 않는다.
- 긴 묵상 입력 시 본문이 자연스럽게 스크롤된다.

#### MOB-003. 입력 중 스와이프/탭 전환 보호

**문제**
장/날짜 스와이프가 컨테이너 전체에 붙어 있어 입력 중 내용 유실 또는 잘못된 장 저장이 발생할 수 있다.

**방향**

- textarea 포커스 중에는 장/날짜 스와이프를 비활성화한다.
- 작성 중 draft가 있으면 날짜 변경, 장 변경, 탭 전환 전에 확인하거나 자동 임시 저장한다.
- 묵상 작성 시 저장 대상 book/chapter/date를 팝업/시트 오픈 시점에 고정한다.

**수용 기준**

- 자유 묵상 작성 중 좌우 스와이프해도 날짜가 바뀌지 않는다.
- 구절 묵상 작성 중 장이 바뀌어도 저장 대상이 변경되지 않는다.
- 닫기/뒤로가기 시 작성 중 내용에 대한 보호 장치가 뜬다.

#### MOB-004. 기본 접근성 정리

**문제**
아이콘 버튼과 작은 액션이 많고, 일부 모바일 터치 타깃이 44px보다 작다.

**방향**

- 주요 아이콘 버튼에 `aria-label`을 넣는다.
- 모바일에서 복사/수정/삭제/닫기/이전/다음 버튼의 터치 영역을 44px 이상으로 맞춘다.
- `html lang`을 한국어 중심으로 정리한다.
- `touch-action: pan-y`가 확대 접근성을 막는지 재검토한다.

**수용 기준**

- Lighthouse 접근성 검사에서 주요 버튼명이 노출된다.
- 구절 묵상 카드의 삭제 버튼을 오터치하지 않을 만큼 터치 영역이 확보된다.
- 화면 리더에서 주요 액션을 이해할 수 있다.

### Phase 1. 성경 읽기 핵심 흐름 재설계

#### MOB-101. 모바일 성경 상단 압축

**문제**
현재 모바일 상단에는 앱 헤더, 역본 선택, 책 선택, 장 선택, 읽음 상태가 누적되어 본문이 아래로 밀린다.

**방향**

- 현재 본문을 `창세기 12장 · 개역한글 ▼` 형태의 compact bar로 합친다.
- 상세 책/장/역본 선택은 바텀시트로 연다.
- 읽음 상태는 보조 텍스트로 줄이고, 실제 행동은 하단 액션 바로 이동한다.

**수용 기준**

- 390×844 화면에서 첫 진입 시 본문 첫 구절이 fold 안에 보인다.
- 책/장/역본 변경은 2탭 이내로 가능하다.
- 상단 높이가 기존 대비 체감상 줄어든다.

#### MOB-102. 구절 액션 바텀시트

**문제**
현재 구절 팝업은 중앙 fixed이고, 하이라이트가 먼저 보여 묵상 작성이 보조 행동처럼 보인다.

**방향**

- 모바일에서는 구절 선택 시 바텀시트를 사용한다.
- 액션 순서는 `묵상하기`, `묵상 보기`, `하이라이트`, `복사` 순으로 재정렬한다.
- 묵상이 있는 구절의 📝 탭은 묵상 보기로 바로 연결한다.
- 구절 복사 후에는 토스트 또는 버튼 상태로 피드백을 준다.

**수용 기준**

- 구절 탭 후 1탭 안에 묵상 작성 화면으로 들어간다.
- 묵상 있는 구절에서 📝 탭 시 바로 묵상 목록이 열린다.
- 하이라이트보다 묵상 작성이 시각적으로 우선 보인다.

#### MOB-103. 구절 묵상 작성 전체 화면

**문제**
작은 팝업 안에서 인용, textarea, 저장 버튼을 다루기 어렵다.

**방향**

- 모바일에서 묵상 작성은 전체 화면 또는 90% 높이 시트로 연다.
- 선택 말씀 인용 영역을 상단에 고정한다.
- 작성 textarea를 충분히 크게 둔다.
- 저장 버튼은 키보드 위 또는 safe-area 위에 고정한다.
- draft 자동 저장 표시를 검토한다.

**수용 기준**

- 키보드가 열린 상태에서도 저장 버튼이 보인다.
- 500자 이상 입력해도 textarea 사용이 답답하지 않다.
- 닫기 시 작성 내용 유실 방지 안내가 나온다.

#### MOB-104. 현재 장 묵상 모바일 복구

**문제**
데스크탑 좌우 패널의 핵심 가치가 모바일에서 사라진다.

**방향**

- 본문 상단 또는 하단에 `이 장의 묵상 n개` 접이식 영역을 둔다.
- 묵상 있는 구절 아래에 1줄 미리보기를 선택적으로 보여준다.
- 📝 아이콘은 해당 묵상으로 바로 이동하게 한다.

**권장안**

첫 구현은 `이 장의 묵상 n개` 하단 시트가 가장 안전하다. 본문 안에 묵상 카드를 모두 끼워 넣으면 읽기 몰입이 깨질 수 있다.

**수용 기준**

- 현재 장에 작성된 묵상을 1탭 이내로 볼 수 있다.
- 묵상 카드에서 본문 구절로 되돌아갈 수 있다.
- 모바일에서도 "이전에 쓴 묵상과 함께 읽는 느낌"이 살아난다.

#### MOB-105. 하단 읽기 액션 바

**문제**
읽음 표시가 본문 끝에만 있어 긴 장에서는 액션 접근성이 떨어진다.

**방향**

- 모바일 하단에 contextual action bar를 둔다.
- 기본 구성은 `이전 장`, `오늘 읽음 표시`, `다음 장`이다.
- 읽음 완료 후에는 `묵상일지 보기`를 함께 제공한다.
- safe-area를 반드시 반영한다.

**수용 기준**

- 장을 끝까지 내리지 않아도 읽음 표시가 가능하다.
- 읽음 완료 후 일지로 1탭 이동할 수 있다.
- 하단 바가 본문을 과도하게 가리지 않는다.

### Phase 2. 묵상일지 회고 흐름 복구

#### MOB-201. 날짜 선택 시트와 오늘 버튼

**문제**
모바일에서 달력이 사라져 과거 묵상으로 이동하기 어렵고, 오늘로 돌아가기 버튼도 없다.

**방향**

- 날짜 텍스트를 탭하면 월간 달력 시트를 연다.
- `오늘` 버튼을 상단에 고정한다.
- 좌우 화살표는 유지하되 날짜 점프를 보완한다.

**수용 기준**

- 3주 전 날짜로 2탭 이내 이동한다.
- 과거 날짜에서 오늘로 1탭 복귀한다.
- 달력 시트에서 읽은 날/묵상 있는 날이 표시된다.

#### MOB-202. 모바일 일지 요약

**문제**
데스크탑의 통계/달력 사이드바가 모바일에서 사라진다.

**방향**

- 일지 상단 또는 하단에 가벼운 월간 요약을 둔다.
- 예: `이번 달 읽은 장`, `묵상한 날`, `최근 작성한 묵상`.
- 전체 통계는 별도 읽기표/통계 화면으로 연결한다.

**수용 기준**

- 모바일에서도 이번 달 묵상 흐름을 확인할 수 있다.
- 통계가 본문 일지 작성 흐름을 방해하지 않는다.

#### MOB-203. 빈 상태 CTA 정리

**문제**
빈 상태와 아래 섹션에서 자유 묵상/기도 작성 버튼이 반복되어 산만하다.

**방향**

- 빈 상태에는 대표 CTA 하나만 둔다.
- 예: `오늘 묵상 시작하기`.
- 누르면 자유 묵상 또는 기도 중 선택하거나, 자유 묵상 입력부터 시작한다.

**수용 기준**

- 빈 상태에서 같은 성격의 CTA가 반복되지 않는다.
- 사용자가 "무엇부터 쓰면 되는지" 바로 알 수 있다.

### Phase 3. 가독성, 진행, 성능 개선

#### MOB-301. 본문 전용 가독성 설정

**문제**
현재 글자 크기는 앱 전체 root font-size에 영향을 주고, 모바일 빠른 조절은 숨겨져 있다.

**방향**

- 성경 본문 전용 font-size, line-height, font-family를 분리한다.
- 모바일 성경 화면에 `Aa` 버튼을 둔다.
- 설정 슬라이더와 헤더 빠른 조절의 값 체계를 통일한다.

**수용 기준**

- 본문 글자 크기를 키워도 헤더/버튼 레이아웃이 무너지지 않는다.
- 모바일에서 본문 가독성을 2탭 이내 조절한다.

#### MOB-302. 읽기표를 진입점으로 만들기

**문제**
읽기표는 진행률 확인에는 좋지만, 다음 읽을 장으로 바로 이동하기 어렵다.

**방향**

- 상단에 `다음 안 읽은 장 읽기` 버튼을 둔다.
- 책 row 탭 시 해당 책의 다음 안 읽은 장으로 이동한다.
- 장 셀 자체를 터치 대상으로 만들지는 신중히 결정한다. 셀이 너무 작기 때문이다.

**수용 기준**

- 읽기표에서 다음 읽을 장으로 1탭 이동한다.
- 시각화와 인터랙션이 충돌하지 않는다.

#### MOB-303. 데이터 호출 최적화

**문제**
하이라이트와 묵상일지 데이터가 전체 목록 재요청에 의존하는 부분이 있어 기록이 많아질수록 모바일 체감이 나빠질 수 있다.

**방향**

- 장 단위 하이라이트 조회를 검토한다.
- 날짜 이동 시 전체 구절 묵상/자유 묵상을 매번 다시 받지 않도록 캐시 또는 범위 조회를 검토한다.
- 일지에서 실제 사용하지 않는 요청을 제거한다.

**수용 기준**

- 날짜를 빠르게 넘겨도 전체 화면이 매번 깜빡이지 않는다.
- 기록이 많은 계정에서도 장 이동이 부드럽다.

#### MOB-304. 탭 상태와 URL 정리

**문제**
성경/묵상 탭이 내부 상태로만 관리되어 새로고침이나 공유, 뒤로가기 흐름이 약하다.

**방향**

- `/bible`, `/journal` 라우트 분리를 검토한다.
- 최소한 activeTab을 URL query 또는 localStorage에 유지한다.
- 뒤로가기 동작이 사용자의 기대와 맞는지 확인한다.

**수용 기준**

- 묵상일지에서 새로고침해도 성경 탭으로 튕기지 않는다.
- 브라우저 뒤로가기 흐름이 예측 가능하다.

### Phase 4. 내비게이션과 정리 작업

#### MOB-401. 하단 탭바 도입 여부 결정

**문제**
상단 탭은 한 손 조작에 불리하지만, 하단 액션 바와 하단 탭바를 동시에 두면 복잡해질 수 있다.

**결정안**

- 1차 개선에서는 전역 하단 탭바를 바로 도입하지 않는다.
- 먼저 성경 읽기 전용 하단 action bar를 안정화한다.
- 이후 프로토타입으로 다음 두 안을 비교한다.

| 안 | 설명 | 장점 | 위험 |
|---|---|---|---|
| A안 | 상단 탭 유지 + 하단 contextual action bar | 변화가 작고 빠르다. | 한 손 탭 전환은 여전히 불리하다. |
| B안 | 하단 앱 탭바 + 화면별 floating CTA | 한 손 조작이 좋다. | 하단이 복잡해지고 본문 공간이 줄 수 있다. |

**수용 기준**

- 성경/묵상/읽기표/설정 접근 경로가 모든 모바일·태블릿 폭에서 존재한다.
- 하단 영역이 2단으로 과도하게 쌓이지 않는다.

#### MOB-402. 죽은 코드와 lint 정리

**문제**
미사용 컴포넌트, 도달 불가 UI, 잔여 API, lint 오류가 모바일 개선 작업을 헷갈리게 한다.

**정리 후보**

- `Sidebar`
- `TrackerModal`
- `dashboard-sidebar` 블록
- `handleToday` 미연결
- `/api/notes` 잔여 호출
- `NoteEditor` 미사용/오류 가능성
- `Search.jsx` 라우트 부재
- 기존 lint 오류

**수용 기준**

- 모바일 개선 대상 컴포넌트가 명확하다.
- `npm run lint`의 기존 오류가 정리되거나, 남길 오류가 문서화된다.
- 도달 불가 UI가 제거되거나 다시 연결된다.

### 6.2 핵심 플로우 테스트

#### 테스트 A. 오늘 이어 읽기

1. 앱을 연다.
2. 최근 읽은 장 다음 장이 열린다.
3. 상단에 왜 이 장이 열렸는지 맥락이 보인다.
4. 첫 구절이 화면 안에 보인다.

합격 기준: 사용자가 별도 탐색 없이 바로 읽기 시작할 수 있다.

#### 테스트 B. 구절 묵상 작성

1. 구절을 탭한다.
2. 바텀시트가 열린다.
3. `묵상하기`를 탭한다.
4. 키보드가 올라온다.
5. 묵상을 입력하고 저장한다.

합격 기준: 저장 버튼이 항상 보이고, 작성 내용이 올바른 구절에 저장된다.

#### 테스트 C. 기존 묵상 보기

1. 📝가 있는 구절을 탭한다.
2. 기존 묵상 목록이 바로 열린다.
3. 묵상을 수정하거나 본문으로 돌아간다.

합격 기준: 기존 묵상 확인까지 1탭이다.

#### 테스트 D. 입력 중 스와이프 보호

1. 자유 묵상을 입력한다.
2. 좌우로 스와이프한다.
3. 날짜가 바뀌지 않거나, 변경 전 보호 안내가 나온다.

합격 기준: 입력 내용이 사라지지 않는다.

#### 테스트 E. 과거 묵상 회고

1. 묵상일지에서 날짜를 탭한다.
2. 달력 시트를 연다.
3. 3주 전 날짜를 선택한다.
4. 오늘 버튼으로 돌아온다.

합격 기준: 3주 전 이동은 2탭 이내, 오늘 복귀는 1탭이다.

#### 테스트 F. 읽기표에서 읽기 시작

1. 읽기표를 연다.
2. `다음 안 읽은 장 읽기`를 탭한다.
3. 성경 읽기 화면으로 이동한다.

합격 기준: 진행률 확인이 바로 읽기 행동으로 이어진다.

## 7. 완료 정의

모바일 개선 1차 완료는 아래를 모두 만족해야 한다.

- iOS Safari와 Android Chrome에서 하단 잘림이 없다.
- 묵상 작성 중 키보드가 저장 버튼을 가리지 않는다.
- 구절 선택 후 묵상 작성까지 1탭이다.
- 📝가 있는 구절에서 기존 묵상 보기까지 1탭이다.
- 현재 장의 전체 묵상을 모바일에서 볼 수 있다.
- 입력 중 스와이프로 날짜/장이 바뀌어 내용이 유실되지 않는다.
- 묵상일지에서 날짜 점프와 오늘 복귀가 가능하다.
- 주요 터치 타깃은 44px 이상이다.
- 읽기표 접근 경로가 모든 모바일·태블릿 폭에서 존재한다.
- 최소 기기 매트릭스에서 수동 QA를 통과한다.

---

## 8. 결정 보류 항목

아래 항목은 중요하지만, 1차 모바일 개선에서 바로 확정하지 않아도 된다.

### 8.1 전역 하단 탭바

하단 탭바는 한 손 조작성에 좋지만, 성경 읽기 하단 action bar와 충돌할 수 있다. 먼저 contextual action bar를 검증하고, 이후 별도 프로토타입으로 결정한다.

### 8.2 오프라인/PWA 강화

PWA manifest는 있으나 서비스 워커가 없다. 개인 묵상 앱 특성상 오프라인은 매력적이지만, 이번 문서의 1차 목표는 모바일 사용성 회복이다. PWA 오프라인은 다음 단계에서 다룬다.

### 8.3 묵상 날짜 모델

현재 구절 묵상은 작성일 중심으로 일지에 보일 가능성이 크다. 장기적으로는 `묵상 대상일`과 `작성일`을 분리하는 편이 명확하다. 다만 데이터 모델 변경이 필요하므로 1차 UI 개선과 분리한다.

### 8.4 장 셀 직접 터치

읽기표 장 셀을 모두 버튼화하면 접근성상 44px 기준을 맞추기 어렵다. 첫 단계는 row-level 이동 또는 `다음 안 읽은 장 읽기` 버튼이 더 안전하다.

## 9. 최종 권고

10점짜리 개선안의 핵심은 "모바일에 기능을 더 넣는 것"이 아니다. 데스크탑의 연구 책상 경험을 그대로 줄이는 것도 아니다.

BibleMate 모바일은 다음 문장으로 정의하는 편이 좋다.

> 오늘 말씀을 바로 읽고, 마음에 닿은 구절을 한 번에 붙잡고, 기록을 잃지 않고, 다시 쉽게 돌아보는 손 안의 개인 묵상 도구.

이 정의에 맞춰 우선순위는 명확하다.

1. 먼저 모바일에서 안 잘리고 안 가려지게 만든다.
2. 그다음 구절 묵상을 가장 빠르고 안전하게 쓸 수 있게 만든다.
3. 그다음 기존 묵상을 바로 볼 수 있게 만든다.
4. 그다음 일지와 읽기표를 회고와 다음 행동으로 연결한다.

이 순서를 지키면, BibleMate의 데스크탑 강점을 해치지 않으면서 모바일에서 "왠지 불편한 앱"이 아니라 "매일 손에 들고 묵상하기 편한 앱"으로 바뀔 가능성이 높다.
