# Implementation Plan v2.3.3 - Auto Read from Verse Note

## 1. 목표
- 구절별 묵상을 저장하면 해당 날짜의 해당 장이 자동으로 읽음 처리되게 한다.
- 사용자가 묵상은 기록했지만 `오늘의 말씀 완료` 버튼을 누르지 않아 캘린더/묵상일지/읽기 진행이 누락되는 문제를 줄인다.

## 2. 범위
- `POST /api/verse-notes` 저장 성공 시 동일 `date + book + chapter` 읽기 기록을 자동 생성한다.
- 이미 동일 날짜/책/장 읽기 기록이 있으면 중복 생성하지 않는다.
- 성경 읽기 화면에서 구절 묵상 저장 후 읽음 상태가 즉시 갱신되도록 읽기 로그를 다시 불러온다.
- 패치 버전 `v2.3.3` 문서와 표시 버전을 정리한다.

## 3. 제외 범위
- 구절 묵상 삭제 시 읽음 기록을 자동 삭제하지 않는다.
  - 사용자가 실제로 읽고 묵상했을 가능성이 높고, 기존 수동 읽음 취소 흐름을 유지하는 편이 안전하다.
- 자유 묵상/기도 저장은 읽음 자동 처리 대상에 포함하지 않는다.

## 4. 구현 단계
1. 서버 `verse-notes` 저장 라우트에 읽기 로그 자동 생성 로직을 추가한다.
2. 프론트 `BibleViewer`에 묵상 저장 후 읽기 로그 갱신 콜백을 호출하는 연결점을 추가한다.
3. `ReadingDashboard`에서 콜백을 전달해 현재 장의 완료 UI가 즉시 반영되게 한다.
4. 버전/문서 파일을 `v2.3.3` 기준으로 갱신한다.
5. 빌드 및 수동 검증 결과를 walkthrough에 기록한다.

## 5. 검증 계획
- `client` 빌드가 성공하는지 확인한다.
- 구절 묵상 저장 후 서버가 `reading_logs`에 동일 날짜/책/장 기록을 하나만 추가하는지 확인한다.
- 동일 구절 묵상을 다시 저장해도 읽기 기록이 중복 생성되지 않는지 확인한다.
- 성경 읽기 화면에서 저장 후 `오늘의 말씀 완료` 상태가 즉시 반영되는지 코드 경로 기준으로 확인한다.

## 6. 리스크 및 대응
- 리스크: 기존 수동 읽음 취소와 자동 생성이 충돌할 수 있다.
  - 대응: 자동 생성은 묵상 저장 시에만 수행하고, 수동 취소 기능은 그대로 유지한다.
- 리스크: 오래된 날짜의 묵상 수정이 해당 날짜 읽음 기록을 새로 만들 수 있다.
  - 대응: 구절 묵상 날짜를 사용해 해당 묵상일의 읽음 기록으로 남기는 것이 데이터 의미상 일관적이다.
