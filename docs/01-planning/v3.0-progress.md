## 이후 단계의 사용자 관점 완료 조건

### 2. Verse Selection

**사용자 목표:** 읽다가 마음에 걸린 절을 생각 없이 한 번 탭할 수 있다.

완료 판단:
- 단일/다중 선택이 손가락으로 자연스럽다.
- 스크롤하다 실수로 선택되는 일이 드물다.
- 선택 때문에 읽던 위치를 잃지 않는다.

### 3. Context Toolbar + Highlight + Copy

**사용자 목표:** 선택한 말씀에 흔적을 남기거나 외부 기록 앱으로 가져가는 일이 빠르다.

완료 판단:
- 하이라이트가 짧은 동작으로 끝난다.
- 주요 버튼을 iPhone에서 편하게 누를 수 있다.
- 여러 절 복사 시 범위와 역본이 정확하다.
- iPad/desktop 1:1 분할에서 외부 기록 앱으로 옮기기 편하다.

기준 구현계획:
`docs/01-planning/implementation-plans/implementation-plan-v3.0-context-toolbar.md`

### 4. Reflection Composer

**사용자 목표:** 말씀을 읽던 흐름에서 자연스럽게 묵상을 적고 돌아온다.

완료 판단:
- iPhone 키보드가 입력/저장 UI를 가리지 않는다.
- 실수로 닫아도 작성 내용이 바로 사라지지 않는다.
- 넓은 화면에서는 본문과 기록을 함께 볼 수 있다.

### 5. Existing Notes Integration

**사용자 목표:** 과거에 남긴 묵상이 조용히 존재하되 읽기를 방해하지 않는다.

완료 판단:
- 묵상이 있다는 사실은 쉽게 알 수 있다.
- 필요할 때 바로 열 수 있다.
- 평소에는 본문보다 눈에 띄지 않는다.

### 6. Responsive 통합 / 회귀

**사용자 목표:** 어떤 창 크기로 열어도 같은 BibleMate처럼 느껴진다.

필수 검수 환경:
- iPhone 13 mini 실제 기기
- iPad/desktop 1:1 Split View급 폭
- Desktop Workspace

### 7. 주변 화면 Visual Cleanup

**사용자 목표:** Journal, Settings, Chart 등으로 이동해도 Reading 화면과 같은 제품처럼 느껴진다.

핵심 Reading UX가 승인되기 전에는 이 단계가 디자인 방향을 주도하지 않는다.

## 실기기 검수 절차

평소 개발은 Codex Remote Control을 이용해 개발 PC에서 진행한다.

검수 가능한 상태가 되면:

```text
Codex 구현
  ↓
lint / build
  ↓
Desktop responsive simulation
  ↓
Codex가 Tailscale 접근용 개발 서버 준비
  ↓
iPhone 13 mini에서 실제 접속
  ↓
사용자 검수
  ↓
피드백 반영 또는 승인
```

- Reading Canvas처럼 읽기/레이아웃 중심 검수는 Tailscale HTTP 개발 서버로 충분하다.
- Clipboard, PWA 등 secure context가 실제 동작에 영향을 주는 단계는 HTTPS/Tailscale Serve 환경을 사용한다.
- Codex는 실기기 검수가 필요한 단계에서 자동 검증 결과만으로 다음 feature를 시작하지 않는다.
- 실기기 검수 결과는 해당 Walkthrough에 기록한다.

## 운영 규칙

1. **이 파일은 상태판이다.** 긴 설계 설명이나 구현 상세를 중복 작성하지 않는다.
2. 단계 상태가 바뀔 때마다 `현재 단계`, `한눈에 보기`, 해당 체크리스트를 함께 갱신한다.
3. Codex가 작업을 시작할 때 이 파일에서 현재 단계와 다음 행동을 확인한다.
4. 작업 종료 시 Walkthrough를 작성한 뒤 이 진행표를 갱신한다.
5. 사용자 승인이 필요한 단계는 승인 없이 `✅`로 바꾸지 않는다.
6. 사용자 실기기 검수가 명시된 단계는 실제 검수 전 `✅`로 바꾸지 않는다.
7. 범위가 바뀌면 먼저 `spec-v3.0.md`를 수정·승인하고 진행표를 맞춘다.
