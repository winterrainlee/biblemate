## 1. 문제 정의

BibleMate는 기능적으로 완성되어 있으나, 시각 언어가 **관리용 SaaS 대시보드**에 가깝다.
"차분하게 성경책을 읽는 나만의 공간"이라는 정서가 화면 어디에도 표현되지 않는다.

### 1.1 현재 디자인 토큰 분석 (`client/src/index.css`)

| 요소 | 현재 값 | 문제점 |
|------|---------|--------|
| Primary 색 | `#2563eb` (Tailwind Blue 600) | 업무용 툴의 대표색. 차가운 기술적 인상 |
| 배경 | `#ffffff` / `#f8fafc` (순백/Slate 50) | 형광등 아래 사무실 느낌. 장시간 독서에 눈부심 |
| 텍스트 | `#0f172a` (Slate 900) | 순백 배경과 결합 시 대비가 과해 딱딱함 |
| 본문 폰트 | Inter + Noto Sans KR (산세리프) | 본문까지 UI 폰트. "책"이 아니라 "화면"을 읽는 느낌 |
| 세리프 (Nanum Myeongjo) | 인용구·묵상 카드에만 제한적 사용 | 핵심 자산이 조연에 머묾 |
| 다크모드 | Gray 800/900 (`#111827`) | 푸른 회색 계열. "밤의 서재"가 아닌 "개발자 IDE" |
| 모서리/그림자 | 4~8px radius, 검정 기반 그림자 | 전형적 웹앱 카드 문법 |

### 1.2 화면별 진단

- **성경 뷰어 (BibleViewer)**: 절 번호가 파란색 볼드, hover 시 회색 배경, 컬럼 구분선 — 데이터 테이블을 읽는 인상. 본문 영역과 UI 영역의 시각적 위계 차이가 없음.
- **헤더 (Header)**: 파란 로고 + 탭 언더라인 — 그대로 Jira에 옮겨도 어색하지 않은 문법.
- **버튼/완료 표시**: 파란 알약 버튼 + 초록 성공색(`#22c55e`) — 신호등 색 체계가 묵상의 정서와 충돌.
- **묵상 카드**: 파란 left-border + 그림자 — "알림 박스" 문법. 손글씨 메모의 정서가 없음.
- **하드코딩 색상**: CSS 전반에 `#3b82f6` 13회 등 Tailwind 팔레트 hex가 직접 박혀 있어, 토큰만 바꿔서는 전체 무드 전환이 안 됨 (§5 Phase 2에서 처리).

핵심 진단: **색·폰트·질감 모두 "도구"의 언어이고 "책"의 언어가 아니다.**
다행히 CSS 변수 체계(`--pk-*`)가 잘 잡혀 있어, 토큰 교체 + 하드코딩 정리만으로 전환 비용이 크지 않다.

## 3. 디자인 방향: "서재(書齋)" 컨셉

> 늦은 오후, 따뜻한 스탠드 아래에서 가죽 표지 성경을 펴는 순간의 색과 질감.

### 3.1 컬러 팔레트

**표면(Surface) 3단 체계** — 단순 배경 2단이 아니라 "책상 → 종이 → 들어올린 종이"의 깊이를 만든다:

- `--pk-color-bg-secondary` (베이지) = 책상·패널 영역
- `--pk-color-bg` (크림) = 기본 화면
- `--pk-color-bg-elevated` (가장 밝은 종이, **신규 토큰**) = 성경 본문 영역·묵상 카드. 중앙 본문이 주변보다 한 단계 밝아 "펼친 종이"로 읽힘

**라이트 모드 — "Paper & Ink"**

| 토큰 | 현재 | 제안 | 의도 |
|------|------|------|------|
| `--pk-color-bg` | `#ffffff` | `#FAF6EF` (따뜻한 크림) | 종이 질감. 눈부심 제거 |
| `--pk-color-bg-secondary` | `#f8fafc` | `#F3EDE2` (밝은 베이지) | 패널·사이드바 |
| `--pk-color-bg-elevated` | (없음) | `#FFFAF2` (밝은 종이) | 본문·카드 표면 (신규) |
| `--pk-color-text` | `#0f172a` | `#3D3529` (세피아 잉크) | 순흑 대신 잉크색, 대비 완화 |
| `--pk-color-text-secondary` | `#64748b` | `#8A7E6D` (따뜻한 회갈색) | |
| `--pk-color-primary` | `#2563eb` | `#8B5E3C` (가죽 갈색, **확정**) / hover `#6F4D2F` | 책갈피·가죽 표지 연상. 흰 글자 대비 5.0:1 |
| `--pk-color-border` | `#e2e8f0` | `rgba(91, 70, 45, 0.16)` (잉크 알파) | 고정 hex 대신 알파 — 어떤 표면 위에서도 자연스러운 옅은 선 |
| `--pk-color-shadow` | `rgba(0,0,0,0.1)` | `rgba(75, 54, 33, 0.10)` | 검정 → 따뜻한 갈색 그림자 |
| `--pk-color-success` | `#10b981` | `#6B7F5E` (세이지 그린) | 신호등 초록 → 차분한 올리브 |
| `--pk-color-danger` | `#ef4444` | `#A4543F` (벽돌색) | 채도 낮춰 정서 유지 |

**Radius 스케일 상향** — 직각에 가까운 카드 → 부드러운 종이 모서리:
`sm 0.25→0.375rem`, `md 0.375→0.75rem`, `lg 0.5→1rem`. (44px 원형 버튼 등 `50%`/`999px` 사용처는 무관)

**다크 모드 — "밤의 서재 (Candlelight)"**

| 토큰 | 현재 | 제안 |
|------|------|------|
| `--pk-color-bg` | `#111827` (푸른 흑색) | `#211C16` (따뜻한 흑갈색) |
| `--pk-color-bg-secondary` | `#1f2937` | `#2B251D` |
| `--pk-color-bg-elevated` | (없음) | `#332C22` |
| `--pk-color-text` | `#f9fafb` | `#EDE5D8` (크림 화이트) |
| `--pk-color-primary` | `#60a5fa` | `#C9A36B` (촛불 금색) — **강조 텍스트·아이콘·링크·테두리 전용** |
| `--pk-color-primary-solid` | (없음) | `#9A6B43` (밝힌 가죽 갈색) — **채움 버튼 배경 전용** (신규) |
| `--pk-color-border` | `#374151` | `rgba(230, 211, 181, 0.14)` (크림 알파) |

**버튼 글자 규칙**: 채움(primary) 버튼의 글자는 라이트/다크 모두 **항상 크림색**(`#FAF6EF` 계열)으로 한다. 다크모드에서 금색 배경 + 검은 글자 조합은 대비 수치는 높아도(8.6:1) 어두운 화면에서 버튼이 가장 밝은 면적이 되어 "조용한 UI" 원칙과 충돌 — 채움 버튼은 다크에서도 가죽 갈색(`--pk-color-primary-solid`)을 쓰고, 금색은 면(배경)이 아닌 선·글자 강조에만 사용한다.

**하이라이트 색**: 라이트 모드는 4색의 색상(hue)을 유지하되 채도를 낮춰 형광펜이 아닌 **색연필 밑줄** 느낌으로 (예: yellow `#fef08a` → `#F2DC92`, green → `#D4E2BD`, blue → `#C9DDEC`, red → `#ECC7BD`).
다크 모드는 불투명 색 대신 **rgba 오버레이**로 전환 — 배경과 자연스럽게 섞이면서 텍스트 대비가 유지된다 (예: yellow `rgba(214,176,89,0.45)`, green `rgba(125,151,104,0.45)`, blue `rgba(97,133,158,0.42)`, red `rgba(166,91,75,0.42)`). 이 방식이면 현재 `.verse-row.has-highlight`에 강제하는 흰색 텍스트 오버라이드도 불필요해질 수 있다.

(선택) 추후 Kindle 방식의 3단 테마 — 종이/세피아/밤 — 로 확장 가능. 현 토글 구조(`:root.dark`)에 클래스 하나만 추가하면 됨.

### 3.2 타이포그래피

> **사용자 실사용 피드백과 검증 경과**: 인용구에 나눔명조를 실제로 써본 결과 가독성이 기대보다 낮았음. 원인 분석 — (1) 나눔명조는 획이 가늘어 화면용으로 약함, (2) 현재 인용구는 `font-style: italic`인데 한글 폰트는 진짜 이탤릭이 없어 강제 기울임(faux italic)이 가독성을 해침, (3) 0.9rem + secondary 색의 조합. 이후 Noto Serif KR·고운바탕·나눔명조를 실제 본문 조건(17px, 줄간격 1.9, 정자)으로 렌더링 비교한 결과 **Noto Serif KR은 본문 기본값으로 충분하다고 확인되어 세리프 기본값으로 확정**. faux italic은 전면 제거한다.

| 영역 | 현재 | 제안 |
|------|------|------|
| 성경 본문 (`.verse-content`) | Inter/Noto Sans KR | **`'Noto Serif KR', serif` 기본값 (확정)** + 설정에서 고운바탕/고딕 선택 가능. 글꼴과 무관하게 줄간격 1.9~2.0, `word-break: keep-all` 적용 |
| 절 번호 (`.verse-num`) | 파란 볼드 | 작은 세리프, `--pk-color-text-tertiary`, 위첨자 느낌 (`font-size 0.7em; vertical-align: super`) — 종이 성경의 절 번호 문법 |
| 장 제목 (nav-select) | 산세리프 1.5rem 볼드 | 세리프 700, letter-spacing 살짝. 책의 장 표제처럼 |
| UI (버튼·탭·설정) | Inter/Noto Sans KR | 유지 — 본문(세리프)과 도구(산세리프)의 위계를 폰트로 분리 |
| 묵상·일기 입력 | inherit | 본문 글꼴 설정을 따름 — 고운바탕 선택 시 "펜으로 쓰는" 정서에 가장 잘 맞음 |

**폰트 결정 (2026-06-12 확정)**: 실제 렌더링 비교 결과 본문 기본값은 **Noto Serif KR**(획 굵기 균일, 본문용 설계)로 확정. **Gowun Batang**을 설정에서 선택 가능한 옵션으로 제공한다 — 설정 화면에 "본문 글꼴" 선택 추가: `명조 (기본, Noto Serif KR) / 고운바탕 (Gowun Batang) / 고딕 (Noto Sans KR)`. 기존 글자 크기 설정과 같은 자리에 배치.

**인용구 스타일 교정**: 기존 인용구(나눔명조 0.9rem 이탤릭 회색)의 가독성 문제는 세리프 자체가 아니라 조건의 문제로 확인됨 — (1) 한글 가짜 이탤릭 **제거**, (2) 크기 0.9rem → 1rem 내외로 상향, (3) 줄간격 1.5 → 1.7 이상. 인용구 폰트도 나눔명조 대신 본문과 동일한 세리프 변수(`--pk-font-serif`)를 따르게 통일.

### 3.3 질감·여백·형태

1. **본문 여백 확대 + 종이 표면**: `.bible-main-content` 최대 폭을 읽기 최적 폭(약 65~70자)으로 제한하고 좌우 여백을 키움. 본문 영역에 `--pk-color-bg-elevated`를 적용해 베이지 배경 위의 "펼친 종이"로. 좌우 묵상 패널은 회색 사이드바가 아니라 **여백 메모(margin note)** 처럼 — 배경 구분을 줄이고 border 대신 여백으로 구획. 2단 컬럼은 유지하되 컬럼 구분선을 제거하거나 더 옅게 — 책의 펼침면 느낌.
2. **hover 효과 완화**: 절 hover 시 회색 박스 배경 → 옅은 베이지 또는 밑줄 점선. "셀 선택"이 아니라 "손가락으로 짚는" 느낌.
3. **그림자 교체**: 검정 그림자 → 따뜻한 갈색 기반 (`rgba(61, 53, 41, 0.08)`), 카드 radius는 8~12px로 통일.
4. **묵상 카드**: 파란 left-border 카드 → 미색 배경 + 옅은 테두리의 "메모지" 문법. 인용구는 세리프 유지하되 이탤릭 제거·크기 상향 (§3.2 인용구 스타일 교정 참고).
5. **완료 버튼/배지**: 알약 파란 버튼 → 세이지 그린 체크 + "오늘의 말씀을 마쳤습니다" 같은 문장형 피드백. 마이크로카피도 정서의 일부.
6. **헤더 시각 무게 축소**: 현재 헤더에 로고·탭·읽기표·글자 크기·다크모드·설정이 모두 노출되어 조작 장치가 먼저 보임. 글자 크기/다크모드/설정을 `···`(더보기) 메뉴로 모으거나 데스크톱에서만 조용한 아이콘으로 유지. 로고 색은 파랑 → 잉크/호두색. (Header.jsx 구조 변경 일부 수반 — 유일한 JSX 변경 허용 항목)
7. **로그인 페이지**: 첫인상 화면. 크림 배경 + 세리프 환영 문구 + 성경 구절 한 줄로 컨셉을 가장 먼저 보여주는 화면으로.
8. **파비콘/앱 아이콘**: 현재 `/logo.png`를 브라우저 파비콘과 apple touch icon으로 함께 사용하므로, v2.3 팔레트에 맞는 새 아이콘으로 교체. 작은 크기에서도 읽히도록 성경책/책갈피/잉크색 이니셜 중 하나의 단순한 실루엣을 사용하고, 크림 배경 + 가죽 갈색/촛불 금색 강조로 로그인/헤더와 같은 첫인상 언어를 공유한다.
9. (선택) 본문 배경에 아주 옅은 종이 노이즈 텍스처(SVG, 2~3% 불투명도). 성능 영향 없는 수준에서만.

### 3.4 마이크로카피 — 언어도 디자인이다

기능 중심 문구를 묵상의 언어로 바꾼다. 색·폰트만큼 분위기에 기여하는 저비용 작업.

| 위치 | 현재 | 개선안 |
|------|------|--------|
| 완료 버튼 | 읽기 완료 | 오늘의 말씀을 마쳤습니다 |
| 묵상일지 섹션 | 읽은 말씀 | 오늘 펼친 말씀 |
| 묵상일지 섹션 | 구절별 묵상 | 마음에 머문 구절 |
| 묵상일지 섹션 | 오늘의 기도 | 기도로 마무리 |
| 빈 상태 | 작성된 묵상이 없습니다 | 아직 남긴 묵상이 없어요 |
| 빈 상태 (사이드 패널) | 전반부 묵상이 없습니다 | 아직 앞부분에 남긴 묵상이 없어요 |
| 구절 액션 | 묵상하기 | 이 말씀 묵상하기 |
| 구절 액션 | 구절 복사 | 말씀 복사 |
| 읽기표 | 전체 진도 | 말씀 여정 |
| 읽기표 | 다음 안 읽은 장 읽기 | 다음 말씀 이어 읽기 |

원칙: **어미는 존댓말("~없어요", "~했습니다")로 통일**한다. 외부 검토안의 반말 어미("~없어")는 앱 전반의 톤과 충돌하므로 채택하지 않음. "여정" 같은 은유는 과하지 않게 — 기능 식별이 어려워지는 수준의 시적 표현(예: "완료율 → 걸어온 길")은 보류.

## 4. 적용하지 않을 것 (Non-goals)

- 레이아웃 구조 변경 (사이드 패널, 모바일 시트, 액션 바 등은 그대로 — 헤더 `···` 메뉴화만 예외)
- 상단 select 3개를 제목형 컨트롤 하나로 압축하는 안(외부 검토 제안)은 **이번 범위에서 제외** — 네비게이션 동작 변경이라 별도 UX 검토 필요
- 컴포넌트 추가/제거, 기능 변경
- CSS 프레임워크 도입 — 기존 `--pk-*` 변수 체계 유지
- 과한 스큐어모피즘 (가죽 텍스처 이미지, 책장 그래픽 등) — 질감은 색과 폰트로만 암시

## 5. 구현 단계

### Phase 1 — 토큰 교체 (효과 大, 리스크 小)
1. `index.css`의 라이트/다크 토큰을 §3.1 값으로 교체 (`--pk-color-bg-elevated` 신설, border/shadow 알파화, radius 스케일 포함)
2. Google Fonts import에 Noto Serif KR·Gowun Batang 추가(각 400/700 웨이트만), `--pk-font-serif`를 Noto Serif KR로 갱신
3. 하이라이트 4색 조정 — 라이트는 채도 완화, 다크는 rgba 오버레이 전환

### Phase 2 — 하드코딩 색상 정리
4. CSS 전반의 Tailwind hex 직접 사용(`#3b82f6` 13곳, `#22c55e` 8곳, `#ef4444` 8곳 등)을 토큰 참조로 치환
5. 그림자·오버레이를 따뜻한 톤 변수로 통일 (`--pk-color-shadow` 갱신)

### Phase 3 — 읽기 화면 (핵심 가치)
6. `.verse-content` 세리프 전환(Noto Serif KR 기본) + 줄간격/`keep-all`, `.verse-num` 위첨자화
6-1. 설정 화면에 "본문 글꼴" 선택 추가 — 명조(기본)/고운바탕/고딕. 글자 크기 설정과 같은 방식으로 CSS 변수(`--pk-font-body`) 전환 + localStorage 저장 (Settings.jsx)
7. 본문 폭·여백·`bg-elevated` 종이 표면·컬럼 구분선·hover 효과 조정, 좌우 패널 여백 메모화 (BibleViewer.css)
8. 장 네비게이션 타이포 세리프화 + nav header 시각 무게 축소

### Phase 4 — 주변 화면 정합
9. 묵상 카드·노트 에디터의 메모지 문법 적용 — 파란 left-border 제거 (NoteEditor, NotePreview, JournalPage)
10. 헤더 시각 무게 축소(`···` 메뉴) + 탭·버튼 색/형태 정리 (Header, Layout, Sidebar)
11. 마이크로카피 일괄 교체 (§3.4 표 기준 — JSX 문자열 치환)
12. 로그인 페이지 첫인상 리디자인 (LoginPage)
13. 파비콘/앱 아이콘 리디자인 및 연결 확인 (`client/public/logo.png`, `client/index.html`, `client/public/manifest.json`)
14. 대시보드·차트·캘린더 색만 팔레트 정합 (ReadingDashboard, BibleChartPage, Calendar)

### Phase 5 — 검증
14. 라이트/다크 × 데스크톱/모바일 4조합 스크린샷 점검
15. 대비(contrast) 검증 — 일반 텍스트 4.5:1, 큰 텍스트 3:1, 버튼·입력창 border·focus ring 시인성 포함 (제안 본문 조합 `#3D3529`/`#FAF6EF` ≈ 9.5:1로 충분. 주의 대상은 secondary 텍스트와 primary 색 위 텍스트)
16. 하이라이트 4색 위 텍스트 가독성 확인 (특히 다크모드 rgba 오버레이)
17. 파비콘/앱 아이콘이 브라우저 탭, 북마크, iOS 홈 화면 기준에서 뭉개지지 않는지 확인
18. 모바일 UX 자산(safe-area, 바텀시트, 전체 화면 묵상 작성, 하단 액션 바) 회귀 없는지 확인

예상 작업량: Phase 1–2는 반나절, Phase 3–4는 화면당 점검 포함 1~2일. 전부 CSS 레벨이라 롤백 용이.

## 7. 수용 기준 (Acceptance Criteria)

"예쁨"이 아니라 아래 조건으로 완성을 판정한다.

1. 성경 읽기 첫 화면에서 본문이 시각적 주인공이다 (조작 UI보다 말씀 영역이 먼저 보인다 — 모바일 포함).
2. 파란 SaaS 느낌이 라이트/다크 모두에서 사라졌다. primary가 링크색이 아니라 책갈피·잉크·나무의 느낌이다.
3. 묵상 카드가 대시보드 카드가 아니라 여백 메모처럼 보인다.
4. 구절 액션 팝업에서 "이 말씀 묵상하기"가 1순위 행동으로 보이고, 하이라이트·복사는 보조 행동으로 보인다.
5. 묵상일지가 데이터 목록이 아니라 하루의 기도 노트처럼 보이고, 빈 상태에서도 차갑지 않다.
6. 다크모드가 개발자 테마가 아니라 밤에 말씀을 읽는 공간처럼 보인다.
7. 브라우저 탭과 홈 화면 아이콘도 새 서재 컨셉과 일관되며, 작은 크기에서도 BibleMate임을 알아볼 수 있다.
8. 본문 텍스트 대비가 WCAG AA를 통과한다 (일반 4.5:1, 큰 텍스트 3:1).
9. 기존 모바일 UX(safe-area, 바텀시트, 전체 화면 묵상 작성, 하단 액션 바)가 그대로 동작한다.

## 8. 외부 검토 반영 기록 (2026-06-12, GPT Pro)

채택:
- 표면 3단 체계(`--pk-color-bg-elevated`) 및 본문 paper surface / 좌우 패널 margin note 컨셉
- border·shadow의 rgba(잉크 알파) 토큰화, radius 스케일 상향
- 다크모드 하이라이트의 rgba 오버레이 방식
- 마이크로카피 개선의 정식 작업화 (§3.4)
- 헤더 시각 무게 축소 (`···` 메뉴)
- 수용 기준 체크리스트 (§7)

불채택 및 사유:
- 다크 배경 `#151922` — 푸른 회색 계열로 "밤의 서재" 컨셉과 모순. 따뜻한 흑갈색(`#211C16`) 유지
- 빈 상태 반말 어미("~없어") — 앱 존댓말 톤과 충돌. 문구는 차용하되 "~없어요"로 통일
- 묵상 카드 `0 8px 24px` 대형 그림자 — "조용한 UI" 원칙과 충돌. 옅은 갈색 그림자 유지
- "완료율 → 걸어온 길" 등 과한 은유 — 기능 식별성 저하 우려로 보류
- 상단 select 3개의 제목형 컨트롤 압축 — 네비게이션 동작 변경이므로 별도 UX 검토로 분리 (§4)

참고: 외부 검토안에는 타이포그래피 전략이 없었음. 세리프 본문 전환(§3.2)은 본 계획의 핵심 차별 요소로 유지.
