# Plan (버전 기획) 워크플로우

다음 버전 개발을 시작하기 전 기능 범위를 정하는 워크플로우입니다.

## 1단계: 프로젝트 현황 분석
1. 다음 파일들을 분석합니다:
   - `docs/01-planning/roadmap.md` - 현재 로드맵
   - `docs/02-specs/architecture.md` - 아키텍처
   - `docs/lessons.md` - 축적된 교훈
   - 최근 `docs/03-logs/dev-log-*.md` - 이슈 및 미해결 항목

2. 분석 결과를 바탕으로 다음을 제안합니다:
   - 🐛 **버그 수정**: 발견된 이슈
   - ✨ **기능 개선**: UX/성능 개선점
   - 🔧 **리팩토링**: 기술 부채

## 2단계: 사용자 희망사항 수집
사용자에게 다음을 질문합니다:
- "이번 버전에서 특별히 추가하고 싶은 기능이 있나요?"
- "불편했던 점이나 개선하고 싶은 부분이 있나요?"

## 3단계: 우선순위 결정 및 버전 범위 확정
1. 제안 항목 + 희망사항을 종합하여 목록화
2. 사용자와 함께 우선순위 결정 (P0/P1/P2)
3. 이번 버전 범위(Scope) 확정
4. 버전 번호 결정:
   - Major (x.0): 아키텍처/핵심 UX 변경
   - Minor (x.y): 신규 기능, UI/UX 개선
   - Patch (x.y.z): 핫픽스, 오타, 보안 패치

## 4단계: 문서 준비 (선택)
- `docs/01-planning/roadmap.md` 업데이트 (확정된 기능 추가)
- `docs/02-specs/spec-vX.Y.md` 초안 생성 (필요 시)

## 완료 후
- "기획이 완료되었습니다! `/branch`로 브랜치를 생성하세요." 라고 안내합니다.
- 이후 흐름: `/branch` → `/feature` → `/pr` → `/deploy`
